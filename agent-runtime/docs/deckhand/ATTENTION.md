# Attention inbox

Cinderdeck stores a bounded observation of each authoritative cause separately from each authenticated actor's preferences. Reading, marking unread, snoozing and waking an item do not answer an approval, finish an agent turn, rerun a task or declare a review complete. The inbox has no completion mutation.

`deckhand.attention.list` accepts up to 100 thread IDs and 16 exact native contexts as refresh hints. The server checks the corresponding projection, native run store, connection state and the actor's latest 100 reviewer queue records. It returns at most 100 causes per page, with actual totals and offsets. The UI rotates larger source inventories in batches every 15 seconds and refreshes when attention semantics change; ordinary transcript updates do not trigger another full source refresh.

Thread requests use their immutable request identity; plans use active plan identity and content; agent failures use the run and error; native failures use the exact installation, workspace generation, run and source-owned outcome digest. Compact native summaries omit step/provenance bodies. A failure resolves only when Cinderdeck reports a matching successful explicit rerun with saved lineage and equal definition/workflow digests in the same native authority; omission never resolves it. Accepted reviewer creation alone does not mean a result is ready: the authoritative reviewer thread must have completed a run without outstanding requests or active work. A review result is agent output, not a GitHub review verdict. Verification items consume successful existing PR-head/evidence assessments; the inbox does not introduce another GitHub poller or infer served-build proof.

Each item carries its cause version, source revision and actor disposition revision. Preference updates refresh the exact stored source target and compare all three revisions atomically. A changed cause resets previous read and snooze preferences; stale updates are refused. Blocking approval, input and sign-in requests cannot be snoozed. Snooze expiry wakes an active cause and never resolves it. Read and snooze preferences survive a server restart and stay separate between actors.

Only a successful read of the same source can resolve a disappeared cause. Missing or deleted threads, connection failures, omitted bounded run history and expired observations remain unknown or last observed. Source observations expire after 75 seconds; successful verification observations expire after five minutes. The UI keeps remembered items visible when a computer disconnects and disables mutable preferences until their source can be checked. Run and reviewer navigation pin the original computer, installation and workspace generation and refuse a recreated target.
