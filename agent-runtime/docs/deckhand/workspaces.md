# Working in a Cinderdeck workspace

A workspace groups project folders, ordinary sessions and operational tools. Expand it in the main sidebar to open a conversation, or use its **+** to start a new chat with saved defaults. Sessions are listed directly under the workspace; there is no lane tree or second session sidebar.

Regular project threads and saved checkout sessions share one list. Sessions from removed checkouts remain readable. Main sessions and siblings default to start time, newest first; later activity and pinning do not reorder them. Drag a session’s grip to set its order among siblings. A main session moves with its descendants; sub-agents stay under their immediate parent. Focus a grip and use Space, arrow keys and Space again to reorder with the keyboard, or Escape to cancel. Saved order is shared by both session lists and scoped to the workspace, execution computer and installation. Filtering, archiving and loading older pages preserve hidden sessions’ saved positions. Sub-agents nest under their immediate parent, with an arrow to expand or collapse each group. Each child retains its own conversation link, status and color. Independently addressable Codex children support the normal composer, steering, queued message controls and stop; follow-ups resume that child’s existing native conversation. Provider-native tasks without an addressable conversation retain their status bar. Forks remain independent sessions. The sidebar shows the first ten main sessions in the saved order with their sub-agents, plus a selected group outside that range when needed. **Show more** opens that workspace’s full Sessions view with search and archived history. Search retains a matching sub-agent’s ancestors and expands the path. Opening a nested session also reveals its parents. The full view loads older saved history in bounded pages. Right-click any session for **Highlight color…** to choose a preset or custom color, or **Use default** to clear it. Session colors persist per execution computer and installation and appear in both lists. **Settings → Appearance → Sidebar highlights** edits the ten presets shared by workspace, session and sub-agent pickers. Presets save locally; editing or resetting them preserves existing row colors. Search, pinning, rename, unread state, archive, restore and delete use the normal thread controls. Include archived loads the archived thread snapshot as well as saved managed history. Archive metadata is also loaded when needed to show an active child beneath an archived parent. Unavailable parents leave the child accessible with a **Sub-agent** label.

Sessions can share a checkout without claims or reservations. Use an optional ordinary Git worktree for independent files. `t3_thread_launch` selects root/new/existing worktrees for a new conversation. `t3_worktree_handoff` moves the current session and can queue a continuation; it never creates a native lane. Worktrees do not automatically allocate or isolate native service ports.

Sessions, Services, Tasks, Workflows, Runs, Recordings and Pull requests are available in the workspace section bar. Files, Diff, Terminal, Browser and External app panels remain beside the conversation. Native operational tools require the execution computer's connection, but disconnected native services and saved generation changes do not lock ordinary agent work. Explicit read-only chats retain provider-enforced read-only access.

**Settings → Workspaces** manages source folders, files and review instructions. The gear beside the workspace plus and star opens these settings. Right-click a workspace for **Highlight color…**; order, favorites, expansion and colors retain their existing client storage keys. Native branch and service controls retain their running-process and data protections.

Legacy checkout records, protocol fields and storage keys remain compatible. Older lane links open the owning workspace's sessions; older CLI lifecycle operations remain available for existing scripts and checkout cleanup. Lane creation and ownership management are not part of the current interface or advertised MCP catalog. See [the whole-app guide](../../../docs/UNIFIED_APP.md) for build and validation boundaries.
